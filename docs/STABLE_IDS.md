# 稳定 ID 规则

> 更新时间：2026-09-09
> 对应 `ARCHX_DIRECTION.md` 的 B1。ID 是 Agent 和人之间唯一的共同指针：Agent 说「这条边」
> 「这个状态」，人要能在界面上定位到同一个东西；人点中一个东西，要能复制出一个引用丢回给
> Agent。所以这份规则一旦定死，之后再改代价很大。

## 1. 形状

```
<种类>:<键>
```

种类决定它属于哪个主题，也决定界面收到一个 ID 时切到哪一页。键的构造见下表。

## 2. 先看 CLAUDE.md 那条硬规则

稳定 ID 属于「接口标识符」，**永远是 ASCII，没有例外**。规则和理由在 `CLAUDE.md` 的
「Hard rule: interface identifiers are never localized」，这里不重复。

它由 `tools/identifier-guard.mjs` 守着，挂在 `npm test` 里（CI 会跑）：事实的键名一律 ASCII，
ID / kind / rule / confidence 这类标识符值一律 ASCII，ID 的种类前缀必须在下面的种类表里登记过。
`warnings`、`condition`、`label` 这些自由文本不在守卫范围内——引擎的中文警告是有意的。

## 3. 另外三条

**一、键里不放行号。** 插一行注释、加一行日志，整个文件的 ID 就会全部换身份——跨快照差分
（B10）会把「加了一句注释」报成「所有函数都换了」，增量重扫（C2）拿旧 ID 去拼新事实会
全部对不上。位置不进 ID，`location` / `definition` 字段里有，按 ID 查表即可。

这一条在 2026-09-09 从源头落实：`function:` 和 `variable:` 去掉了行号，派生层五处
「从 ID 抠 file/line」改成查 `view.variables` 表。

**二、键里不放数组下标或簇号。** 重扫一次就变。

**三、内容指纹也不行。** 用 AST 结构算哈希，加注释确实不变，但**改一行代码就变**——而改代码
才是常态，那样 ID 会在每次真实修改时漂，比行号更糟。

## 4. 种类表

### 事实层（引擎产出，进 `partition.json`）

| 种类 | 键 | 唯一性依据 |
| --- | --- | --- |
| `function` | `<路径>:<名字>` | C 语言同一文件内不能有两个同名函数（`static` 重名只跨文件，路径已区分）。C++ 重载未验证，见下节 |
| `variable` | `<路径>:<名字>` | 只收文件级变量，局部变量不进事实。索引本身就以 `(路径, 名字)` 为键 |
| `external` | `<名字>` | 只有声明没有定义的符号，按名字聚合就是它的全部身份 |
| `main` / `task` / `isr` / `callback` | `<入口函数名>` | 执行单元，一个入口函数对应一个单元 |

864 函数 / 248 变量的真实工程上实测：去行号后 **0 冲突**。

### 派生层（视图产出，同时供 MCP 和界面）

| 种类 | 键 | 主题 |
| --- | --- | --- |
| `unit` | `<目录或文件>` | 依赖：`.c` 和同名 `.h` 合成的叶子 |
| `ext` | `<路径前两段>` | 依赖：区域外的模块 |
| `lib` | `<库文件名>` | 依赖：闭源库 |
| `exec` | `<执行单元 ID>` | 执行关系 |
| `fsm` | `<路径>:<变量名>` | 状态转换：一台状态机 |
| `state` | `<机器键>/<状态名>` | 状态转换：一个状态 |
| `loop` | `<路径>:<函数名>#<函数内第几个>` | 顺序与时间 |
| `res` | `<路径>:<变量名>`，取不到变量时退回 `<名字>` | 共享与并发 |
| `mem` | `<模块>` | 内存占用：一个模块 |
| `sym` | `<文件>:<名字>` | 内存占用：一个符号 |

`res` 和 `fsm` 都是把变量 ID 去掉 `variable:` 前缀再拼，不留双前缀。

### 渲染键（不是跨快照指针）

`round` / `frame` / `box` / `cl` / `close` / `yield` 只在一次展开内唯一，用于 React 对齐和
就地展开，每次重新计算。它们带行号是合适的，不要求跨快照稳定，也不该被 Agent 引用。

## 5. 各自会在什么时候漂

| ID | 编辑注释 | 改函数体 | 重命名 | 移动文件 | 在前面插入同类对象 |
| --- | --- | --- | --- | --- | --- |
| `function` / `variable` | 稳 | 稳 | 漂 | 漂 | 稳 |
| `fsm` / `state` / `res` / `sym` | 稳 | 稳 | 漂 | 漂 | 稳 |
| `loop` | 稳 | 稳 | 漂 | 漂 | **漂** |

重命名和移动文件时漂是可以接受的——那本来就是「换了个东西」。`loop` 那一格是没办法：循环
没有名字，同一个函数里可能有十几个（实测最多 12 个），只能靠「第几个」区分。在中间插入一个
新循环会让它后面的全部漂，但那是结构性修改，不是编辑噪声。

## 6. 还没定的

**C++ 重载。** 同一文件里 `Motor::set(float)` 和 `Motor::set(int)` 会撞同一个 `function` ID。
唯一会碰到的语料是 `odrive`（清单里标着 `not-yet-verified`），等 C5 摸清它的重载形态再决定
要不要加参数签名后缀——不为一个没验过的语料提前把规则做复杂。

**跨重扫的稳定性验证。** 目前只验了「同一份输入两次扫描 ID 一致」和「去行号后无冲突」，
还没验「改动源码后未改动部分的 ID 保持不变」，那是 B10 的前提。
