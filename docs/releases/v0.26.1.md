# ArchCheck v0.26.1 — first public release

ArchCheck recovers the runtime structure of C/C++ firmware from the code that actually compiles:
entries, tasks, interrupts, callbacks and timers; what each one reaches; which of them touch the same
state; loops, state machines and per-unit order. The scan is deterministic and offline. The facts are
read through an agent (MCP) or as pictures (local page, VS Code panel).

A fact set describes one commit. Change the code, scan again.

## Install

```
pip install archcheck
claude plugin marketplace add SHAR-K/ArchX && claude plugin install archx@archx
```

Then ask the agent to scan a project. It needs `clangd` and build information
(`compile_commands.json` or a Keil `.uvprojx`); when either is missing, `scan_project` says which and
gives the command for that project's build system.

Live demo, no install: https://shar-k.github.io/ArchX/

## What is in this release

- **Engine** (`archcheck` on PyPI): clangd-based extraction to `architecture.json`. Bare-metal,
  FreeRTOS, ESP-IDF and Arduino-ESP32 profiles; Keil and compile-database inputs; optional linker-map
  facts. CLI output is English.
- **MCP server** (Claude plugin `archx`): `scan_project`, `list_code_facts`, `read_code_facts`,
  `read_fact_object`, `show_code_facts`, `focus_code_fact`. Facts are sliced by theme, object and
  field path.
- **Local page**: every scan writes a single `archx-facts.html` next to the facts. It opens offline
  and holds that project's facts, so it stays on your machine.
- **VS Code extension** (VSIX, win32-x64, engine bundled): the same six themes in a panel.

## Known limits

- With more than one Keil project or target in a repository, the scan picks the first one and the
  memory theme may read another target's `.map`. Pass the project explicitly until this is fixed.
- Task-to-task conflicts are not judged yet; ISR-to-task and ISR-to-ISR are.
- The VSIX is Windows x64 only. The PyPI engine runs anywhere Python 3.10+ and clangd run.
