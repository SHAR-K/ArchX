# ArchX VS Code 插件使用说明

> **状态：大部分已作废（2026-09-09）。** 里面讲的架构工作台、目标架构树、右侧 Agent、
> 提案审批、worktree 执行都删了。插件现在只有一件事：扫描仓库、在面板里看代码事实。
> 命令只剩 8 个，视图只剩分区树。当前形态看 `ARCHX_DIRECTION.md`。

> 插件版本：`0.25.1`

## 当前能力

- 在 Activity Bar 中提供架构工作区、可展开的目标架构树和扫描结果视图。
- 目标架构树按父子节点展开，并在节点下展示代码绑定和负责范围；单击绑定可直接跳转到代码行。
- 目标架构画布不再保留固定详情栏；节点契约、所有权、代码绑定、验收标准和验证计划在右侧 ArchX“节点详情”标签按需查看。
- 在文件树中右键目录创建架构分区。
- 使用 React Flow 展示目标架构和 ArchCheck 实际文件依赖。
- 目标架构默认聚合为可展开的层级容器，只显示层间依赖；展开后可选择组件并查看其依赖摘要。
- 目标架构画布右上角可按依赖拓扑从上到下重新排列当前可见层级，并保存新位置。
- 跨越多个架构层的依赖使用独立侧边通道和可见标签，避免与相邻层主干依赖重叠。
- 目标架构节点实时投影全部原生工作流状态：Claude 对话进行中为黄色、Stop 正常结束为绿色、执行待审查为橙色、执行或验证失败为红色，并显示工作流和短会话 ID。
- 叶子节点状态颜色覆盖节点背景和外框；带子节点的父层保持中性，父层自身会话只着色标题栏，后代状态以数量摘要显示，展开后仅具体子节点独立着色。
- 容器展开后子节点是真实画布节点（ELK compound 布局），组件级依赖可见；依赖层级锁定为泳道，反向依赖与未声明依赖直接画在图上。拖动节点后 ELK 以交互模式重新整理并重算路由，布局运行在 Web Worker 中。
- 右上角只有"重新排列"和"叠加层"两个按钮，叠加层提供执行域着色与代码所有权；右键节点菜单按上下文最多四项；`F` 聚焦、`E` 展开、`T` 追踪依赖、`Esc` 退出。节点内容随缩放级别递进展开。
- Extension Host 每 300ms 监听本机会话索引；同一 Claude 会话继续追问会重新变黄，下一次 Stop 后转绿，无需手动刷新工作台。
- Claude Hook 通过工具完成事件维护会话心跳，`SessionEnd` 和 API 失败会把活动会话标记为已中止；右侧节点会话也可手动修正未收到结束事件的黄色状态。
- 单击目标架构节点会从 Claude Code 重新聚焦到右侧 ArchX，并直接打开该节点详情；双击仍跳转代码入口。
- 提供目标架构、代码地图、候选架构和落地检查视图。
- 可在右侧代码事实检查器中把实际模块、目录、文件或函数映射到目标架构节点。
- 在代码地图选择模块、目录、文件或函数后可执行“架构分析与优化”；ArchX 自动创建或复用分析分区并扫描，Agent 先提交带证据和置信度的当前子架构。确认后才解锁“仅保存分析/继续优化”，优化结果仍进入统一候选架构审批。
- 落地检查按文件和函数统计已映射、未映射和冲突，并显示每个目标节点的事实覆盖量。
- 双击架构节点或实际文件跳转到 VS Code 编辑器。
- Windows x64 VSIX 内置带 Python 运行时的 ArchCheck 独立引擎，无需安装 Python 或配置引擎路径。
- ArchCheck 分区事实保存在 VS Code 扩展存储中，不污染项目仓库。
- 在 VS Code Secondary Side Bar 注册独立 ArchX Agent 视图。
- 可一键安装 ArchX Claude Code 插件，在 Claude Code 原生侧栏使用按需加载的 Skills 和 ArchX MCP。
- 原生 Agent 通过 MCP 读取当前选中节点；候选架构和变更单直接进入 ArchX 审批状态，不再依赖聊天中的特殊 JSON。
- 原生实现通过 MCP 创建独立 Git worktree 和执行租约；Claude Hook 强制限制 `ownedPaths` 减去 `excludedPaths` 的有效范围、声明的验证命令和 `.archx` 审批状态。容器节点可以执行，但只能修改子节点未认领的公共资产（CMakeLists、Kconfig、公开头文件）。
- 原生验证证据、修改文件和 Git Diff 回写到 `.archx/runs/`，可在右侧“执行审查”中接受或拒绝。
- 不同节点在有效范围不重叠时可使用独立 Claude 会话和 Git worktree 并行执行（容器残余范围与其子叶子互不冲突）；可能重叠的范围由 MCP 拒绝并发启动。
- Claude Hook 首次处理执行事件时把真实 `session_id` 回写到对应 Run，执行审查可查看完整会话 ID。
- 右侧“原生工作流”提供讨论、提案、实现和验证四个入口，并显示 MCP 当前项目、分区、节点、所有权、验收条件和代码事实摘要。
- 点击工作流后自动新建 Claude Code 原生对话，并复制包含节点名、稳定 `nodeId` 和可用 `changeId` 的 `/archx:*` 输入。
- Claude 发送工作流命令后，Hook 把真实 `session_id` 绑定到当前节点；右侧“节点会话”可直接重新打开精确会话，复制 ID 作为兼容兜底。
- 展开目标架构层时立即以至少 `1.35` 倍缩放聚焦该层；`archx.ui.fontScale` 可在 `85%` 到 `150%` 间即时调整工作台和 Agent 字号。
- Agent 回复、工具过程、权限、会话续接和 Diff 全部由 Claude Code 原生页面管理。
- 架构讨论结果先进入“候选架构”；新增、更新、删除和依赖关系均需审批，现有节点更新按稳定 `nodeId` 显示逐字段修改前后差异，未勾选字段不应用。
- Agent 提交同级同名新增节点会被拒绝并提示改用 `updatedNodes`；正式更新保留节点 ID、关系、代码映射、分区绑定和节点会话历史。
- 右侧“节点详情”可为当前节点及其后代创建删除提案；系统根节点禁止删除，未经工作台批准不会修改正式架构。
- 节点详情可创建变更单；项目约束、节点契约、所有权、验收和验证门禁全部通过后才能批准并进入受约束实现。
- 实现结果保存为独立执行记录，右侧可查看修改文件、Git Diff、范围审计和逐命令验证证据。
- 只有验证与 ArchCheck 架构复检均通过时才能接受；接受后生成提交、合并到当前分支、回写节点状态并刷新分区事实，拒绝则清理 worktree。
- 落地检查页执行所有权、映射冲突、未声明跨节点依赖、失效绑定和循环依赖规则，并提供架构检查点回滚。
- 架构讨论在 Claude CLI 层明确拒绝 Bash、Edit、Write、NotebookEdit 和 Task，只开放 Read、Glob、Grep。
- Agent 工作流定义包含前置条件、上下文、工具、输出和执行后检查。

当前 ArchCheck 方式是“建立全仓事实后投影分区及直接边界”，还不是增量局部扫描。界面会明确显示事实来源，不能把当前投影视为完整架构违规门禁。

## 构建和安装

在 ArchX 仓库根目录运行：

```powershell
npm install
npm run package:extension
code --install-extension .\apps\vscode\archx-win32-x64-0.25.1.vsix --force
```

安装后执行 `Developer: Reload Window`，或重新打开 VS Code。

开发时可在 ArchX 仓库中按 `F5`，选择 `Run ArchX Extension` 启动 Extension Development Host。

## 使用流程

1. 用 VS Code 打开目标代码仓库根目录。
2. 点击 Activity Bar 中的 ArchX 图标。
3. 尚未初始化时运行命令 `ArchX: 初始化当前项目`。
4. 在 Explorer 中右键负责的目录，例如 `src/drivers`。
5. 选择 `ArchX: 将目录设为架构分区`。
6. 在“架构工作区”标题栏点击扫描图标，或在分区右侧点击扫描。
7. 运行 `ArchX: 打开架构工作台`。
8. 使用“目标架构/代码地图/落地检查”切换视图；存在待审提案时会出现“候选架构”。
9. 在目标架构中选择节点，点击工具栏右侧的节点详情图标，在右侧 ArchX 侧栏查看完整契约。
10. 首次使用执行 `ArchX: 安装 Claude Code 原生工作流`，安装随 VSIX 发布的 Skills 和 MCP。
11. 在右侧“原生工作流”选择讨论、提案、实现或验证；插件会新建 Claude 对话，并复制带节点上下文的 `/archx:*` 输入。
12. 在 Claude Code 输入框粘贴，检查节点和变更单信息，补充本轮要求后发送。
13. 在 Claude Code 原生页面查看会话、权限、工具调用和 Diff；发送后目标节点自动变黄，回复停止后转绿；右侧“节点会话”同步显示状态，点击记录可重新打开精确会话。
14. 架构讨论成功返回结构化方案后，打开“候选架构”，逐项确认新增和删除、逐字段确认现有节点更新，并确认依赖；阻断问题清零后应用。也可在右侧“节点详情”直接发起当前节点的删除提案。
15. 在目标架构选择开发节点，打开右侧“节点详情”，创建变更单并执行门禁批准。
16. 在 Claude Code 编辑器中调用 `/archx:deliver`；MCP 校验获批变更单并创建隔离 worktree，Claude 按返回路径进入执行区。
17. 同一交付会话运行节点声明的验证命令，并按真实失败证据循环修正，最后把证据写入执行记录。
18. 验证通过后点击“接受并合并”；插件先执行 ArchCheck 分区复检，再提交、合并并更新架构状态。也可拒绝并删除 worktree。
19. 在“代码动态”标签查看当前文件、代码绑定、分区摘要和最近修改。
20. 在“代码地图”选择模块、目录、文件或函数，点击“架构分析与优化”；插件自动建立分析分区、扫描并进入 `/archx:design`。
21. Agent 提交当前子架构后在工作台确认或要求修正；确认后可仅保存分析，也可继续讨论优化并提交候选架构。审批后再按目标叶子节点创建变更单，进入 `/archx:deliver`。

映射规则单独保存在 `.archx/project.json` 的 `architecture.mappings` 中。模块使用目录通配规则，文件使用精确路径，函数使用 ArchCheck 符号 ID；已有 `codeBindings` 作为代码入口锚点参与解析，但不会替代正式映射规则。

## ArchCheck 配置

Windows x64 安装包已经内置 ArchCheck、Python 运行时和 PyYAML。插件按以下顺序选择运行时：

1. `archx.archcheck.enginePath` 显式指定的独立程序或源码仓库。
2. VSIX 中与当前平台匹配的 `engines/win32-x64/archcheck.exe`。
3. ArchX 开发仓库旁或桌面的 `archcheck` 源码仓库，仅作为开发回退。

可配置项：

```text
archx.archcheck.enginePath
archx.archcheck.pythonPath   # 仅外部源码引擎使用
archx.archcheck.keilProject
archx.archcheck.keilTarget
```

没有编译数据库或 Keil 配置时，插件调用 ArchCheck 低精度源码扫描。该模式可以展示文件事实，但不包含可靠的符号、调用和全局变量关系。

## 当前限制

- 当前只发布 `win32-x64` 独立引擎；Linux、macOS 和 Windows ARM64 还需要各自在目标平台构建专用 VSIX。
- ArchCheck 扫描尚未提供逐阶段 NDJSON 进度事件。
- 架构规则当前是内置规则集合，尚未提供项目自定义规则文件、抑制策略和基线管理。
- Claude Code 扩展没有公开“预填并发送提示词”的稳定接口，因此 ArchX 当前通过剪贴板交接 Skill 命令，需要在原生输入框粘贴后发送。
- ArchX 已索引节点对应的 Claude `session_id`，但直接从画布跳转到原生扩展中的指定历史会话仍依赖 Claude Code 扩展提供稳定命令接口。
- 候选架构支持新增、按稳定 ID 更新、删除和选择性应用，但还没有图形化重挂父节点；更新关系本身仍需通过新增/删除关系能力完善。
- worktree 当前按整次执行接受或拒绝，尚未支持逐文件或逐 hunk 选择。
- 当前只使用第一个 VS Code workspace folder。
- 局部优化当前一次只支持一个模块、目录、文件或函数；多选子图和多个不连续路径的边界合并尚未实现。
- Claude Code 插件目前通过本地 marketplace 安装；升级 ArchX VSIX 后需要重新执行一次“安装 Claude Code 原生工作流”。

## 下一步

当前降低首次配置、打包、布局微调和一般易用性优化的优先级。功能主线是：

```text
设计决策与验证知识沉淀
→ Prompt 上下文压缩和 Token 预算可视化
→ 自定义架构规则、基线和抑制
→ Linux/macOS/Windows ARM64 平台独立引擎
→ 逐文件/逐 hunk 审批和设计决策沉淀
```

Agent 交互主线已经形成“原生对话 + ArchX Skill + ArchX MCP + Hook 门禁 + 执行记录”；后续重点是 Codex 适配、上下文压缩和更细粒度的变更审批，而不是继续复制完整聊天客户端。
